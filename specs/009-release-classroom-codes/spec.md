# Feature Specification: 一次性課堂碼釋放與重用

**Feature Branch**: `codex/009-release-classroom-codes`

**Created**: 2026-11-26

**Status**: 規格／設計／任務已產出；使用者回報C1雙組行為與C2新版圖意皆已確認，D1已修訂，分析重驗見analysis.md；尚未實作。

**Input**: 結束課堂永久關閉並釋放加入碼供新課堂重用；新加入僅查有效碼，學生在開放期間恢復固定原課堂及原組別；關課後學生不能再看內容，教師歷史與回填依賴保留。學生採獨立登入／加入頁，加入後不常駐登入提示。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 永久關課並讓碼可重用 (Priority: P1)

教師結束一次性課堂後，原課堂永久關閉，原碼不再提供加入，之後可分配給新課堂。

**Why this priority**: 讓碼可循環使用，同時維持一次性課堂的結束界線。

**Independent Test**: 在隔離資料建立 A／碼 C、結束 A，再使不同內部識別的 B 取得 C。強制選 C 僅為驗收手段，不表示教師可指定碼。

**Acceptance Scenarios**:

1. **Given** A 開放且 C 有效，**When** 有權教師確認結束 A，**Then** A 及其未結束活動結束，C 失去對 A 的加入效力，歷史與原歸屬保留。（FR-001、004、010）
2. **Given** C 已釋放且無新有效對應，**When** 新學生輸入 C 及組別，**Then** 顯示「查無此課堂」，不建立加入資格。（FR-003）
3. **Given** C 可再分配，**When** B 取得 C，**Then** B 與 A 的內部識別不同，C 只對 B 有效，A 不復活。（FR-002、005）
4. **Given** C 已分配給 B，**When** 原教師重送結束 A，**Then** A 仍結束，B 的碼、狀態及資料均不變，不再次釋放 C 的新對應。（FR-006）
5. **Given** 學生或非擁有教師直接請求結束／重開／改配 A，**When** 驗權，**Then** 拒絕；任何人均不能重開已結束課堂。（FR-001、009）

---

### User Story 2 - 關課後停止學生存取 (Priority: P1)

學生在課堂開放期間依原資格恢復原堂／原組別；整堂結束後停止查看題目、答案與歷史結果，只提供結束提示及重新加入流程，不因同碼重用進入新堂。教師仍保留歷史。

**Why this priority**: 符合一次性課堂的存取期限，並隔離新舊課堂。

**Independent Test**: A 甲／乙組保留有效證明；課堂開放時可恢復，A 結束後以原授權、原證明、舊網址及直接結果請求均不得取得學生內容；B 重用碼也不使舊資格有效。

**Acceptance Scenarios**:

1. **Given** A 開放且原資格有效，**When** 重整或重連，**Then** 恢復 A／原組別，不重新解析碼。（FR-007）
2. **Given** A 已結束，**When** 原學生重整、重開或恢復 A，**Then** 只收到結束提示或加入入口，不取得題目、答案、組別作答、順位或歷史結果，也不自動加入 B。（FR-007、017）
3. **Given** A 已結束且舊授權／證明尚未到期，**When** 直接請求狀態內容、結果清單或指定活動結果，**Then** 後端拒絕學生內容存取；不能只在前端隱藏。（FR-009、017）
4. **Given** 活動已結束且已結算但 A 仍開放，**When** 原學生查看結果，**Then** 沿用 D06 的勝組及本組可見範圍；整堂結束才停止學生結果存取。（FR-011、017）
5. **Given** A 已結束，**When** 有權教師讀取原歷史或回填依賴，**Then** 資料與原歸屬完整，不因學生權限終止而刪除。（FR-010）

### User Story 3 - 手動加入同碼的新課堂 (Priority: P2)

學生想加入後來使用同碼的新課堂時，重新輸入課堂碼與組別，成功後才取得新資格。

**Why this priority**: 支援下一堂課且維持新舊資格界線。

**Independent Test**: 只持 A 原證明時無 B 權限；明確輸入 C 與組別加入 B 後才有 B 新紀錄，A 資料不被改寫。

**Acceptance Scenarios**:

1. **Given** A 已關閉且 B 以 C 開放，**When** 學生重新輸入 C 與組別並送出加入，**Then** 建立 B 資格；組別依 B 解析，不繼承 A 的組別識別、答案或順位。（FR-008）
2. **Given** 只持 A 證明或重開舊頁，**When** 沒有重新送出碼與組別，**Then** 無 B 權限。（FR-007、008）
3. **Given** 已手動加入 B，**When** A 舊請求／晚到回應抵達，**Then** 不把 A 資格、狀態或結果套到 B，也不以 B 資格讀 A；顯示「課堂已結束」與「加入其他課堂」，按下回獨立加入頁。（FR-012）
4. **Given** 學生尚未加入，**When** 以有效碼及組別加入，**Then** 先顯示獨立加入頁，成功後進課堂內容，沒有常駐登入提示／加入表單；失敗時留在加入頁顯示可重試錯誤。（FR-016、018）
5. **Given** 學生正在 A 課堂頁，**When** 得知整堂已結束，**Then** 移除原題目與結果顯示，停在「課堂已結束」及「加入其他課堂」；按下按鈕才回獨立加入頁。（FR-016、017）

### User Story 4 - 並發仍維持唯一歸屬 (Priority: P1)

關課、分配與加入同時發生時，每次成功結果均有固定且可解釋的課堂歸屬。

**Why this priority**: 避免同碼雙堂、關錯堂或加入結果悄悄轉移。

**Independent Test**: 控制下列操作先後確認順序，逐項核對；這是未執行的驗收預期。

**Acceptance Scenarios**:

| 案例 | 系統確認順序／競態 | 預期 |
| --- | --- | --- |
| R1 | 兩新堂同時爭取 C | 最多一堂取得 C；另一堂取得不同有效碼或明確失敗。 |
| R2 | 加入 A 在結束 A 前確認 | 紀錄固定 A／原組別；之後看到 A 已結束，不轉移 B。 |
| R3 | A 已結束，新分配未生效 | C 無有效對應，顯示「查無此課堂」。 |
| R4 | B 的 C 對應生效後，明確新加入確認 | 取得 B 新資格，不恢復 A。 |
| R5 | 請求已解析 A，關課／重配先完成，再確認加入 | 不沿用過期 A 判定，也不在同請求悄悄加入 B；拒絕或要求明確重試。 |
| R6 | 關課未成功完成 | 不報成功、不使 C 同時對另一堂有效；不留下課堂已結束但活動仍可受理的半完成成功狀態。 |
| R7 | 重送結束 A 與 B 使用 C 同時發生 | 重送只針對 A，不影響 B 對應。 |
| R8 | A 舊活動提交與關課競爭 | 沿用 D02／004；關閉先確認則拒絕，已成功受理仍固定 A 的指定活動／組別。 |

### Edge Cases

- 空白組別、輸入不合格與嘗試過多沿用原限制；碼格式依 FR-014，不因重用繞過檢查。
- 單一活動結束而課堂仍開放，不釋放碼；仍由其他開放堂占用的碼不可回收。
- 不同教師／課程同時爭取同碼，仍至多一個有效對應；不保證分配給誰。
- 無活動、準備中、搶答中或已結算活動的課堂均可由有權教師結束；未結束活動須一併結束。
- 分配碼耗盡或操作失敗須明確失敗，不搶用仍有效碼、不回假成功。
- 格式驗收：當 AB123 有效時，「ab123」與「 AB123 」對應同堂；「AB 123」不等同 AB123，無有效對應顯示「查無此課堂」；空白、非文字或原始輸入超過 32 字元回輸入錯誤。
- 分配驗收：A 結束後，原碼在無冷卻等待下可由同教師／同課程、同教師／其他課程或另一教師的新堂取得；分配時仍需唯一性檢查，教師介面不提供指定碼。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 課堂成功結束後永久關閉，不允許重新開始、新活動、新加入或新提交；保留課堂歷史。
- **FR-002**: 整個新加入入口中，一碼任一時刻至多對應一個開放課堂，不能因教師／課程不同而雙重有效。新課堂使用獨立且不重用的內部識別。
- **FR-003**: 新加入只找有效碼對應的開放課堂；格式合格但無有效對應時一律顯示「查無此課堂」，不查歷史碼授權。原學生關課提示仍為「課堂已結束」。
- **FR-004**: 結束時同步終止該堂未結束活動及新加入／提交能力，釋放該堂對碼的有效占用；對外不可出現已關課卻仍可憑原對應加入的狀態。
- **FR-005**: 可回收僅限已結束課堂釋放、且當下無其他開放堂占用的碼；不回收課堂／活動／組別識別、資格或歷史，不因單一活動結束釋放。釋放後立即可由全系統分配，無冷卻期；不保證下一堂立即取得同碼，依 FR-015。
- **FR-006**: 有權教師重複結束同堂不得新增生命週期變更、重做結算或釋放新堂的碼對應。回已結束或明確衝突皆須守此界線；具體回應留待契約核對。
- **FR-007**: 加入紀錄、授權與恢復證明固定內部課堂 ID 及原組別。恢復只驗原證明及原歸屬，不以碼重新解析；有效證明只可在課堂仍開放時恢復原堂／原組別；整堂結束後不再授予學生內容存取。失效／缺少證明須拒絕，不以碼取代。此變更取代本輪原採 D16 的關課後學生歷史恢復。
- **FR-008**: 加入重用碼的新堂必須明確重新輸入碼及組別並完成新加入；不得由舊證明、同組名、背景重連或舊頁自動轉入。內部課堂 ID 由系統處理，不要求使用者操作。
- **FR-009**: 教師管理驗證登入與課程／課堂擁有權，學生不得管理碼／課堂。狀態、恢復、提交、結果及歷史入口皆驗證課堂與適用組別，不能僅以前端隱藏或碼相等授權。
- **FR-010**: 活動、題目快照、答案、順位、勝組、結算快照、固定講義版本、回填報告及失敗恢復依賴，永遠固定原課堂／活動歸屬；碼重用不得轉移、刪除、改寫或公開給新堂學生。
- **FR-011**: 關課不等於結算完成。已結束且已結算活動在課堂仍開放時依 D06 向學生公布；教師依原權限讀取歷史、依 D11 取得不可變回填快照，不因關課失去權限；未結算仍未就緒，不產生假勝組，不自動重送未知回填。
- **FR-012**: 關課、分配、加入與提交競態須符合 US4 R1–R8；晚到請求／回應不改歸屬，過期課堂判定不得在同次加入中轉投新堂。
- **FR-013**: 分配或關課失敗須明確呈現且可重試，不留下可用的半完成對應；不在本輪指定重試次數或技術機制。
- **FR-014**: 沿用現有格式：系統產生 5 碼，前兩碼為大寫英文字母 A–Z，後三碼為數字 0–9（如 AB123）。加入輸入去除首尾空白並轉大寫，故 ab123 與 AB123 視為同碼；不移除中間空白或另做字形轉換。沿用現有輸入門檻：須為非空白文字，原始輸入長度最多 32 字元；空白、非文字或超長顯示輸入錯誤，其他無有效對應的輸入顯示「查無此課堂」，不新增不同格式碼。
- **FR-015**: 課堂成功結束時移除其有效碼占用，該碼立即可供全系統建立新課堂時由系統自動選用，無冷卻期，跨教師／課程均可分配。教師不人工指定碼，不保證下一堂取得剛釋放的碼；仍有效碼永不回收，分配仍須符合 FR-002、US4 R1～R7。
- **FR-016**: 學生使用獨立登入／加入頁，仍輸入課堂碼及組別，不新增 Google 學生登入。加入成功後進入課堂，不常駐登入提示。整堂結束時顯示「課堂已結束」與「加入其他課堂」按鈕，按下才回獨立加入頁；不自動跳轉或自動加入同碼新堂。
- **FR-017**: 關課成功提交後，新開始的學生內容讀取交易一律拒絕，即使原授權或恢復證明尚未到期亦同。每次內容讀取在同一交易開始即查權威的原課堂狀態並驗權，涵蓋狀態全文、結果清單及個別活動結果；確認為CLOSED時僅提供必要結束提示或拒絕，不回傳題目、作答、順位或勝組資料。關課前已在同一讀取交易合法驗證OPEN的快照回應可能晚到，前端依FR-017a拒絕套用；不承諾收回關課前已合法閱讀或自行保存的內容。課堂仍開放時，活動結束結果可見規則不變。
- **FR-017a**: 學生畫面一旦確認課堂已結束，須清除已顯示的題目／答案／結果；即使是關課前已合法取得的快照回應，也不得在此後套用。重新整理、瀏覽器返回舊頁與晚到回應均須確認有效狀態，不得把結束頁還原為可讀課堂。
- **FR-018**: 加入失敗時在原加入頁提供當次錯誤及可操作的重試提示；暫時斷線顯示重連狀態，不一律當作未登入。課堂仍開放且原資格有效時可恢復原堂／原組別；資格失效時提供重新驗證或返回加入頁的操作。頁面入口、加入成功導頁與關課後返回行為統一依FR-016。


### Key Entities *(include if feature involves data)*

- **課程／教師**：課堂上層歸屬與管理權來源，碼重用不轉移擁有權。
- **一次性課堂**：固定 classroom_id、開放／已結束狀態及原活動關係；結束不可逆。
- **有效碼對應**：碼當下可加入的課堂關係，最多一堂；釋放此對應不刪歷史。
- **歷史配碼事實**：原堂曾使用該碼的事實，供追溯而非加入／恢復授權；不預設獨立資料表或顯示方式。
- **課堂組別／加入紀錄**：固定 classroom_id、group_id 與原瀏覽器證明；同組名不代表跨堂同一組。
- **活動與歷史依賴**：固定 activity_id、講義版本、作答、結果與回填／恢復關係，不追隨碼新對應。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: US1／US4 案例中，同碼有效堂數始終不超過 1，已結束課堂重開成功數為 0。
- **SC-002**: 兩組原學生的重整／重開／恢復／跨堂請求案例中，誤入新堂及取得其他組資料次數均為 0；無有效對應的新加入皆顯示指定文案。
- **SC-003**: 手動加入案例只建立新堂資格；原活動、答案、順位、勝組與回填依賴無改寫／轉移；缺有效證明或整堂已結束時恢復學生內容的成功數為 0。
- **SC-004**: R1–R8 每種先後順序均有可重現驗收結果；失敗／重送不造成雙重有效碼、錯誤釋放或跨堂提交。
- **SC-005**: 由有權教師與至少兩組學生完成人工「關課 → 結束提示 → 返回獨立加入頁 → 手動加入新堂」，全程無須操作內部ID。同碼重用及舊資格隔離另以受控fixture驗證，不要求正式人工環境隨機抽到相同碼，也不新增正式指定碼功能。此為未執行目標，不是通過聲明。
- **SC-006**: 加入成功後課堂頁常駐登入提示／加入表單數為0；關課成功提交後，兩組原學生在所有受保護內容入口新開始的讀取交易均無題目或結果資料返回。畫面確認CLOSED後，題目／結果顯示數為0，關課前合法快照的晚到回應亦不得使其重新顯示。

## Assumptions

- 依據憲章 I／II／IV／V／VI、共同需求 D02／D06／D09／D11–D16 及 [008 使用者確認紀錄](../008-teacher-course-workspace/validation.md#使用者確認一次性課堂碼釋放與重用2026-11-26)。本輪由使用者於 2026-11-26 確認；同日使用者回報同學已審圖，審查者姓名與具體結論未提供。後續使用者於同日回報「C1 C2皆已確認」，本輪D22雙組行為及新版圖意依使用者回報列為已確認；確認者姓名與獨立紀錄未提供，不虛構。003具體介面／分工仍依T003留實作前核對。
