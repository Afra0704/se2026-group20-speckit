# Feature Specification: 從活動結果預覽回填與原課堂組名

**Feature Branch**: `codex/012-result-writeback`
**Created**: 2026-11-27
**Status**: Implemented, validation in progress — 三故事已接線；自動回歸與人工／真 Sheets 驗收分開記錄，尚未宣稱整體完成
**Input**: [Issue #19](https://github.com/Afra0704/se2026-group20-speckit/issues/19)；使用者提供同學 #16 組號契約，詢問接續 #19。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 從選定活動進入回填 (Priority: P1)

教師查看目前活動或歷史活動結果時，按「預覽回填講義」即可核對該活動的勝組答案及原講義，不必查找或輸入活動識別碼。

**Why this priority**: 消除手動選錯場次與講義版本的風險。
**Independent Test**: 建立兩場同名活動、共用同份講義但各用不同版本及答案，逐場由結果進入預覽並重新整理、返回，核對始終對應原活動。

**Acceptance Scenarios**:

1. **Given** 教師擁有一場已結束且已結算活動，**When** 從目前活動或歷史結果點入，**Then** 顯示該活動的回填預覽，尚未寫入來源。
2. **Given** 同名活動、不同課堂或重用講義，**When** 預覽、重新整理或返回結果，**Then** 活動、講義版本與結算版本始終保持原對應，不以名稱或目前活動替換。
3. **Given** 活動尚未結束、結束但結算未完成、或結算完成而無勝組，**When** 要求預覽，**Then** 分別提示「活動尚未結束」、「結果尚未結算完成」、「沒有勝組可回填」，均不寫入。

### User Story 2 - 辨識原課堂、勝組與歷史版本 (Priority: P1)

教師能在預覽與報告辨認課程、課堂、活動、講義版本、來源分頁及勝組，即使課堂已結束或講義已從清單移除。

**Why this priority**: 歷史資料仍須能正確回填，顯示文字不能取代資料歸屬。
**Independent Test**: 兩堂各有第 1 組，使用不同答案；關閉原課堂並移除講義清單項目，仍可由原活動查看正確預覽與報告。

**Acceptance Scenarios**:

1. **Given** 原課堂第 42 組勝出，**When** 看預覽或報告，**Then** 顯示「第 42 組」，不以內部組別識別當組名。
2. **Given** 不同課堂各有第 1 組，**When** 看任一活動預覽，**Then** 依該活動原課堂查找勝組，不跨堂或依現行加入碼推測。
3. **Given** 勝組不存在或不屬原課堂，**When** 建立或讀取預覽／報告，**Then** 明示資料對應錯誤且阻止該資料進入新寫入，不猜測組名；既有操作與診斷證據仍保留。
4. **Given** 課堂已結束或講義清單已移除，**When** 原教師查看歷史，**Then** 保留原講義版本與來源；其他教師與學生直接請求亦不能越權。

### User Story 3 - 確認、重新授權與安全恢復 (Priority: P1)

教師先核對預覽，再確認寫回原 Google Sheets；失敗或授權失效時可在原活動脈絡下接續。

**Why this priority**: 新入口必須保留既有覆寫、回讀與恢復保障。
**Independent Test**: 使用受控來源模擬授權失效、來源變動、部分及未知寫入結果，核對回到原活動且恢復不重送已完成題；真人另以測試副本驗證。

**Acceptance Scenarios**:

1. **Given** 有勝組及無勝組題混合，**When** 確認回填，**Then** 僅寫入勝組題的原目標格，無勝組題略過，其他內容、合併及格式保留。
2. **Given** 來源值不同而需覆寫，**When** 教師尚未逐項同意，**Then** 不覆寫；恢復時清楚區別原已同意覆寫與此次新衝突。
3. **Given** Sheets 授權失效，**When** 重新連接成功、取消或失敗，**Then** 保留原活動及既有預覽／操作脈絡，成功後可明確接續，不能自動切換到最新活動。
4. **Given** 部分成功或結果未知，**When** 從報告啟動恢復，**Then** 先回讀來源再建立恢復預覽，維持原勝組與結算版本，不重送已完成題；確認前再次驗證權限及來源。

### Edge Cases

- 活動同名、課堂碼重用、講義重匯入，不改變舊活動所指向的資料。
- 無勝組題顯示「無勝組／略過」；有勝組識別但查無原堂組別則為資料錯誤，兩者不能混同。
- 預覽與報告連結直接開啟、重新整理、返回及登入／授權恢復，均重新驗權並保留原活動。
- 講義移除僅影響清單；來源雲端檔案真被刪除或失去權限時，明示來源錯誤，保留歷史。
- 時間空值或無法辨識時使用 #20 的安全顯示規則，不使預覽／報告無法開啟。
- 不為「第一組」、01 等舊測試名稱補轉換；不清除既有非測試資料、歷史或回填紀錄。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 教師目前活動與歷史活動結果 MUST 提供「預覽回填講義」，自動固定所選活動；一般操作不要求抄寫內部識別。
- **FR-002**: 系統 MUST 以原活動固定的講義及結算版本產生預覽；勝組、答案與目標格由系統查出，不能採信使用者指定的替代內容。
- **FR-003**: 預覽、確認結果與恢復 MUST 保持相同活動脈絡，涵蓋重新整理、返回與重新授權。
- **FR-004**: 預覽及報告 MUST 顯示課程、課堂、活動名稱、區別場次所需時間、講義名稱／版本、來源分頁；內部識別僅留必要診斷區。
- **FR-005**: 勝組 MUST 依活動原課堂及原組別識別查出，再使用 #16 的「第 N 組」格式；不得用標籤反推答案、順位或回填對應。
- **FR-006**: 勝組不存在／跨堂 MUST 明確報錯並阻止新增寫入；不得把內部識別、他堂同號組或推測名稱當作勝組標籤。
- **FR-007**: 未結束、未結算、無勝組 MUST 有不同提示；部分題目無勝組時，僅略過該題並明示。
- **FR-008**: 教師擁有的關課歷史及已移除講義歷史 MUST 仍可預覽回填；每次讀取／確認／恢復均驗證教師資格及原資料歸屬。
- **FR-009**: 寫入 MUST 先預覽再明確確認；沿用既有逐項覆寫同意、重送保護及回讀一致才成功的行為。
- **FR-010**: 來源變動、部分成功與未知結果 MUST 沿用既有回讀恢復流程；不得更換勝組、重新結算或重送已完成題。
- **FR-011**: Sheets 重新授權 MUST 沿用 PR #14 的安全返回與接續，保留當前活動及必要回填脈絡。
- **FR-012**: 時間 MUST 使用 #20 共同規則及真實欄位語意，清楚區分建立、結束、結算、預覽及回讀時間；不以建立時間假充結束時間。
- **FR-013**: 本功能 MUST 保留既有資料與紀錄，僅對辨識的目標空格回填；不擴充 CSV／xlsx 下載，不修改 #16 學生組號輸入規則。

### Key Entities *(include if feature involves data)*

- **活動脈絡**：原教師、課程、課堂及活動，含顯示名稱與語意明確的時間。
- **原課堂組別**：組別身分隸屬特定課堂；組號與顯示標籤不是跨堂識別。
- **固定講義版本**：活動建立時選定的講義版本與來源分頁；不因清單移除而消失。
- **結算快照**：活動固定版本的勝組及答案；無勝組與錯誤組別對應分開處理。
- **回填預覽／操作報告**：維持活動、講義版本、結算版本及來源格位，包含覆寫同意、寫入／回讀狀態及原操作恢復關聯。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 目前與歷史結果各一次點擊即可進入指定活動的回填預覽流程，需手動輸入識別碼的步驟為 0。
- **SC-002**: 同名活動、跨堂同組號、重用講義、移除講義與關課歷史的驗收案例，100% 保持正確活動／勝組／來源版本。
- **SC-003**: 預覽與報告所有有效組號以「第 N 組」呈現，內部組別識別誤作組名的案例為 0；不存在與跨堂組別均拒絕新增寫入。
- **SC-004**: 未結束、未結算、無勝組各有可區分提示；其他教師及學生的直接存取案例全部遭拒。
- **SC-005**: 授權恢復、來源變動、覆寫、部分／未知結果及恢復案例全數維持原活動與勝組，已完成題重送數為 0。
- **SC-006**: 真實 Sheets 測試副本逐格核對勝組答案正確、無勝組略過，非目標值、合併及格式變更數為 0；未執行前保留待驗收。
