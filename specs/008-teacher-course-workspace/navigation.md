## 已查證的外部能力與 plan 待研究

2026-11-25 查閱 Google 官方資料：Google Picker 提供網頁內的 Drive 選檔；網頁方案需要選檔用的 access token，官方樣例另涉及 Picker／Drive 服務、API key、App ID 與來源設定。這是候選技術，不是已設定或已選定方案。

來源：[Picker overview](https://developers.google.com/workspace/drive/picker/guides/overview)、[Web sample](https://developers.google.com/workspace/drive/picker/guides/web-picker-sample)。

Plan 必須先處理以下內容，不能假設現有 007 Sheets 授權足夠：

1. 官方選檔與替代方案比較，最小權限、同 Google 身分、選檔結果後端重新驗權；不能直接相信前端傳來的檔案識別。
2. 若 Picker 需要瀏覽器短期 access token，須明確界定與 007「後端授權秘密不交前端」的關係；不能直接把既有包含 broad Sheets 權限的後端 token／refresh token／client secret 暴露前端。必要技術差異記錄並交同學核對。
3. 發起課程、來源方式及返回位置的續接／過期／多分頁規則，沿用已有的一次性 OAuth 流程與安全返回限制，不用任意 next URL。
4. 講義清單可見性、刪除與新活動建立／匯入版本的原子規則，保留不可變歷史及回填依賴。既有 007 資料不可在規格階段刪除或遷移。
5. 新頁面如何沿用 005/006/007 與 001/002/003 邊界，舊網址與導覽相容方式、前端測試及教師兩組學生人工驗收。

這些是技術規劃待辦，不是要求使用者提供 token 或改 Google Cloud 的指令。圖意互審與 plan 尚未執行。
