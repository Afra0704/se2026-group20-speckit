# Feature Specification: 學生查看完整題目文字

**Created**: 2026-11-25
**Status**: 計畫階段 — 原有共同功能的實作補齊；使用者回報同學已審圖，尚未實作。
**Input**: 「我想讓學生看得到題目，不只是題號。」

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 學生在課堂直接閱讀題目 (Priority: P1)

老師匯入講義並建立活動後，學生能在題號旁直接讀到講義的完整題目文字，準備時可看，開啟搶答後才可輸入與提交。

**Why this priority**: 學生不必另開講義對照題號，就能理解要回答的問題。
**Independent Test**: 單題講義匯入、確認並建立活動，兩組學生對照來源逐題檢查文字；開始後不需重新加入即可作答。
**Acceptance Scenarios**:

1. **Given** 已保存含題目文字的講義版本，**When** 老師建立活動，**Then** 同堂兩組均看到每題題號、完整文字及對應作答欄。
2. **Given** 活動準備中，**When** 學生看題，**Then** 可閱讀但不可填答；老師開啟後同一活動可填答，文字不變。
3. **Given** 題目含換行、中文、英文或特殊符號，**When** 顯示，**Then** 內容與順序完整、換行可辨識，長文字可換行閱讀，不執行其中的標籤或程式文字。

### User Story 2 - 題組每個小題與作答欄正確對應 (Priority: P1)

學生看到一個主題號下的全部小題標號、各自題目與作答欄，仍以整組一次提交。

**Why this priority**: 只顯示題組標號不足以判斷每格要回答什麼，且錯位會造成錯答。
**Independent Test**: 使用至少兩小題的題組及移動欄列的另一份講義，逐一對照題目、標號與欄位。
**Acceptance Scenarios**:

1. **Given** 主題 1 含兩個小題，**When** 活動顯示，**Then** (1) 的文字對應第一格，(2) 的文字對應第二格，維持同一主題號與一個提交單位。
2. **Given** 來源題號或欄列位置不同，**When** 老師匯入並確認，**Then** 學生文字與作答對應仍正確，不靠固定題號或座標。

### User Story 3 - 老師確認文字與活動版本 (Priority: P2)

老師在匯入預覽可核對將顯示給學生的題目，建立後固定該版文字，不因來源後續修改而讓同場學生讀到不同題目。

**Why this priority**: 題目與作答識別必須同版，才能公平作答並正確回填。
**Independent Test**: 確認活動後修改來源文字並重新匯入新版，檢查舊活動仍顯示原版、新活動使用新版。
**Acceptance Scenarios**:

1. **Given** 匯入取得題目文字，**When** 老師預覽，**Then** 能逐題／逐小題核對學生將看到的內容，與填空識別一致。
2. **Given** 活動已建立，**When** Sheets 文字被修改或新增講義版本，**Then** 舊活動文字不被替換；新活動依選定版本顯示。
3. **Given** 某小題文字缺漏或無法唯一對應，**When** 老師預覽新匯入，**Then** 明確標出題號／小題問題，修正後才可確認供全文顯示使用，不猜測或以答案補題目。

### Edge Cases

- 先前只保存題號的開發講義版本：明示該版未包含文字，老師須重新匯入確認；學生不得誤以為只有題號即為全文功能正常。既有版本不偷偷改寫，不在顯示時即時抓來源補字。
- 沒有題目、標號重複、合併範圍造成歧義：沿用動態辨識錯誤處理，阻止發布不完整的新版本。
- 題目含 HTML 或腳本片段：當一般文字顯示，不能變成可執行網頁內容。
- 工作表的「作答」格已填內容：不把這些答案作為題目、預填值或預覽提示公開給學生。
- 刷新、斷線恢復及換活動：文字與當前活動版本同步，新舊題目不混用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須從已支援的 Google Sheets 題目欄動態取得每個作答項目對應的完整題目文字，供老師預覽核對，不能從作答格推測或生成。
- **FR-002**: 學生必須在活動建立後看見題號、題目文字、題組小題標號及對應作答欄；準備、開始、結束的可作答規則沿用 005。
- **FR-003**: 題組內每個小題的文字必須與該小題標號及作答欄一一對應，維持整組提交、單次順位及同一勝組。
- **FR-004**: 已建立活動必須固定所選講義版本的文字、順序及作答識別；刷新、重連及來源修改不得改變該活動內容。
- **FR-005**: 題目文字必須保留可讀的換行、Unicode 及一般符號；長內容可換行閱讀，不以固定高度截掉正文。任何標籤或程式片段必須當純文字呈現。
- **FR-006**: 學生可見資料只增加作答所需題目，不得包含來源儲存格座標、憑證、來源作答格原值或他組答案；既有公布結果規則維持不變。
- **FR-007**: 新匯入版本的文字缺漏或對應不唯一時必須在確認前指出問題並阻止發布；舊版缺字則明示重新匯入，不猜題、不即時替換已建立活動。
- **FR-008**: 完整文字功能不得改變同堂單活動限制、教師操作權限、題數、作答欄數、題目識別及正確回填的對應關係。
- **FR-009**: 移除內建示範清單、示範作答受理、啟動設定與切換入口。正式服務不可用時必須明確失敗，不得自動切換示範資料；獨立自動測試可使用只存在測試目錄的受控資料與替代端。

### Key Entities

- **題目／小題文字**：來自講義題目欄的內容，與一個作答項目對應，包含可讀換行與符號。
- **講義版本**：固定題號、小題、文字、順序與填空識別，老師確認後不可變。
- **活動題目**：活動選定版本的內容，學生只取得安全顯示資訊。
- **匯入預覽**：教師核對全文與作答對應的畫面，能指出缺漏或歧義。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 教師及兩組學生驗收單題與題組範本時，全部題目與小題文字、標號、欄位的對應正確，沒有遺漏或錯位。
- **SC-002**: 穩定本機環境下，建立活動後兩組在 5 秒內看到完整題目，無須另開 Sheets 或重新加入。
- **SC-003**: 換行、長文字、Unicode 及 HTML／腳本文字測試全部可讀，且沒有文字被當成網頁指令執行或正文被截掉。
- **SC-004**: 來源修改、刷新、復線及換場案例中，活動文字版本全部正確；安全檢查不出現來源答案、座標或他組資料外洩。
- **SC-005**: 移除示範模式後，正式清單／顯示／受理服務缺少的測試全部回應約定不可用錯誤，不建立假講義或受理答案；不存在可啟動的示範入口與專用資料寫入路徑。

## Assumptions

- 本迭代只顯示文字，不包含圖片、影片、儲存格顏色或字型的原樣複製，以及數學式專用排版；保留公式儲存格可見文字的既有辨識語意。
- 來源結構沿用已確認表頭及合併範圍規則；完整題目文字不需要 AI 生成或摘要。
- 005 已完成自動驗證，人工回報的舊服務問題已修正但仍待重驗；006 不代表 005 人工任務完成。
- 舊開發版本可重新匯入，不做跨版資料遷移；保留已建立活動與回填識別，具體契約演進方式在 plan 定義。
