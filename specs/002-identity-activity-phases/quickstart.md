# Phase 1 驗證指南：002 身分與活動階段

## 準備

準備 Python 3.13.x、uv 和三個獨立瀏覽器工作環境。以一名教師與兩組學生操作。先以 001 替代清單提供三道簡答題及兩個版本，並以 003 替代服務提供受理紀錄、結算中及已結算資料。測試使用虛構身分與作答。

可先使用內建的本機測試清單操作 002。測試清單的識別為 `demo`，可用版本為 1、2。真實 001 清單服務與 003 受理／結算服務就緒後，再進行整合驗收。

```powershell
uv sync --python 3.13
$env:GUIDED_NOTES_SECRET_KEY = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
$env:GUIDED_NOTES_DEMO_CATALOG = '1'
uv run flask --app guided_notes:create_app init-teacher teacher
uv run flask --app guided_notes:create_app run --host 127.0.0.1
```

在 `http://127.0.0.1:5000/teacher` 登入並用 `demo` 建立活動，再於兩個獨立的瀏覽器工作階段開啟 `http://127.0.0.1:5000/`，輸入活動碼及不同組名。開啟搶答後可以提交測試答案，會存入本機示範資料表。正式順位、結算及回填仍需 003／001，示範活動結束後會顯示結算中。停止伺服器後可用 `uv run pytest` 執行自動驗證。

## 自動驗證與三端操作

| 案例 | 步驟 | 預期 |
| --- | --- | --- |
| FR-001／002、D11 | 教師建立活動後，替代 001 發布新版本，再建立第二個活動。另嘗試使用不可用版本。 | 第一活動仍是原版，第二活動可用新版。不可用版本不建立活動。 |
| FR-003／004、A03 | 甲組準備中加入並看題，直接要求提交。教師開始後乙組加入，兩組各提交。 | 準備中即可看題，但提交遭拒。搶答中兩組可按組提交。 |
| FR-004／006、A04 | 以學生和非管理教師直接呼叫開始、結束與其他活動的讀取介面。 | 拒絕且無階段改變或資料外洩。 |
| FR-007、A06 | 用兩條 SQLite 連線和可控的同步點分別測試先受理再關閉，以及先關閉再進入受理交易。加入請求同樣測試關閉競爭。 | 先受理者列入，先關閉者之後的提交或新加入均拒絕。交易失敗不留下部分受理資料。 |
| FR-003／004、A06 | 關閉後以管理教師重開，以未加入者輸入有效代碼。 | 都拒絕，階段仍為已結束。 |
| FR-005、A08 | 三端各於開始與結束後重整。讓乙組離線後切換階段，再恢復網路。 | 六次首個成功讀取都取得當前狀態，乙組授權仍有效時自動恢復。記錄同步延遲與兩秒候選目標的差異。 |
| FR-005、D09 | 讓原組別短期授權過期，同一瀏覽器關閉頁面後返回，依提示驗證原組別。再以另一瀏覽器、已清除資料的瀏覽器、其他活動的加入證明重試。 | 原加入證明有效且匹配該活動才恢復原組別的結果存取。其餘均拒絕。 |
| FR-006、D06、A04 | 檢查準備中、搶答中、結算中及已結算的頁面與原始回應。 | 結束前無他組作答資料。結算中只有狀態。結算後教師及兩組學生各只取得契約允許的欄位。 |
