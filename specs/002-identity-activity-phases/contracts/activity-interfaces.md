# Phase 1 介面契約

## 模組介面

| 呼叫 | 輸入 | 結果與失敗 |
| --- | --- | --- |
| 002 → 001 查清單版本 | 已授權教師、`list_id`、`version` | 回傳可用性及有序題目 `question_id`、`position`、`display_number`、可選顯示文字。無權限、空清單、版本不存在或資料不完整時拒絕建立活動。 |
| 003 → 002 驗證受理 | 同一 SQLite 寫入交易、可信授權參考、`activity_id`、`question_id` | 解析該學生的組別、最新階段及固定題目。非搶答中、授權或資源不符即拒絕。003 在相同交易寫入受理紀錄並等待提交成功。 |
| 003 → 002 驗證結果視角 | 可信授權參考、`activity_id` | 回傳角色、可操作活動及適用組別。003 依此組裝允許欄位。 |
| 003 → 001 回填資料相依 | `list_id`、`version`、`question_id`、勝組答案 | 由 001 解析原版本的格位。D05／D07／D09／D10 的格式與重試行為仍由 001 釐清。 |

## 同源 HTTP 入口

以下路由與欄位是 SpecKit 組內設計。所有寫入入口驗證 CSRF，所有受保護入口從伺服器授權查得角色與範圍。

| 方法與路徑 | 輸入與成功回應 |
| --- | --- |
| `POST /teacher/session` | 教師登入憑證。驗證成功回應 204 並建立工作階段。 |
| `POST /activities` | 教師授權及清單識別、版本。回應 201，包含新活動識別、活動碼、階段、階段版本。 |
| `POST /activities/{id}/start`、`POST /activities/{id}/close` | 活動管理教師。提交狀態變更後回應 200 與最新階段及版本。 |
| `POST /activity-memberships` | 活動碼及自填組別名稱。拒絕空白組名，同活動相同組名（去除首尾空白後）對應同一組別。準備中或搶答中回應 201，含對應活動、組別、階段及可顯示題目，並設定原加入證明與短期授權。 |
| `POST /activities/{id}/result-access` | 原瀏覽器的加入證明。伺服器由原加入紀錄取得原組別，請求不可指定組別。活動已結束且證明有效時回應 204，授予該活動的結果讀取權。 |
| `GET /activities/{id}/state` | 管理該活動的教師及已授權學生共用此入口，回傳 `activity_id`、`phase`、`phase_version`、角色及可顯示題目。僅學生視角含自身組別資料。拒絕活動範圍不符的教師或學生。後端禁止快取。 |
| `POST /activities/{id}/submissions` | 題目識別及答案。003 從可信授權取得組別與角色。交易成功後回應 201。 |
| `GET /activities/{id}/results` | 依下表回傳作答狀況或結算結果。後端禁止快取。 |

共同行為：無有效授權回應 401，授權或範圍不符回應 403，活動階段與操作衝突回應 409，輸入不合格回應 400。交易忙碌且無法完成回應 503，禁止假回報成功。錯誤使用穩定的機器可讀代碼，對未授權請求省略活動內容及代碼有效性的細節。

## D06 結果欄位

| 階段 | 管理教師 | 學生 |
| --- | --- | --- |
| 準備中 | 題目與階段 | 組別、題目與階段 |
| 搶答中 | 可讀取各組作答狀況 | 無其他組作答、順位或勝組欄位 |
| 已結束，結算中 | 結算狀態 | 結算狀態 |
| 已結束，已結算 | 每題各組答案、順位及勝組 | 每題勝組名稱及答案、本組答案及順位 |

後端按視角建立獨立回應資料。回應、HTML 或頁面預載資料均套用同樣的欄位限制。匯入憑證、回填格位及原加入證明不得出現在學生資料。
