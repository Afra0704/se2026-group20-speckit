# 功能規格：002 身分與活動階段

**功能分支**：`codex/002-identity-activity-phases`

**建立日期**：2026-11-23

**狀態**：已納入兩組確認的 002 行為規則

**輸入**：教師引用已匯入的題目清單建立活動，學生按組加入，教師開啟與結束搶答，各端同步並在重新整理後取得活動狀態。

## Clarifications

### Session 2026-11-23

雙組同意由使用者於本次對話轉述。確認者、實際確認日期或跨組紀錄連結待補，見[共同需求的變更紀錄](../../docs/shared-requirements.md)。

- 截止如何判定？→ 系統確認結束前已成功受理的答案才計入（D02／D03）。
- 如何授權？→ 教師獨立登入並受活動管理權限約束，學生輸入活動碼並自填組別。自填組別由使用者提出，待雙組確認（D04）。
- 結算後可看什麼？→ 教師看全部組別結果，學生看勝組名稱與答案及自身答案與順位（D06）。
- 如何恢復狀態？→ 授權有效時自動恢復原活動及適用的組別，並讀取最新階段（D09）。
- 活動使用哪版清單？→ 建立時固定清單版本與題目識別（D11）。
- 何時可以加入與看題？→ 開始前和搶答中都可加入，加入即可看題（D03）。
- 結束後能否重開？→ 準備中 → 搶答中 → 已結束，已結束不可重開（D03）。
- 結束後原授權失效如何看結果？→ 重新驗證原組別後可取得結果存取權（D09）。
- 換裝置後能否恢復？→ 只有同一瀏覽器保有可驗證的原加入紀錄才可恢復。換裝置、換瀏覽器或清除紀錄後無法恢復。使用者已回報兩組確認（D09）。

## 使用者情境與驗收

### 使用者故事 1 – 教師建立及控制活動（P1）

教師使用已匯入的題目清單建立活動，依上課進度開啟與結束搶答。

**優先理由**：活動與題目範圍是學生加入、作答與結算的共同依據。

**獨立驗收**：以一份有效匯入清單和教師身分測試建立、開啟、結束。

1. **給定**教師可使用含三題的已匯入清單，**當**建立活動，**則**活動具有獨立識別，並保留三題的順序與識別。
2. **給定**教師所管理的活動，**當**依序開啟與結束搶答，**則**活動狀態依序反映已開始與已結束。
3. **給定**找不到所選清單或教師無權使用它，**當**嘗試建立活動，**則**顯示清單無法使用並且不建立活動。
4. **給定**活動已引用某版清單，**當** 001 重新匯入同一講義，**則**既有活動的題目識別和順序維持原版本。教師可引用新版建立另一活動。
5. **給定**活動已結束，**當**有管理權限的教師再次要求開啟，**則**拒絕，階段仍為已結束。

### 使用者故事 2 – 學生按組加入並同步狀態（P1）

學生以所屬組別加入活動，可以在原頁面及重新整理後看到目前階段。

**優先理由**：兩組學生需要在同一活動下依相同階段參與。

**獨立驗收**：以一名教師及兩個不同組別的學生開啟三個獨立操作環境。

1. **給定**兩組有有效的活動碼並自行填寫各自的組別，**當**一組在開始前、另一組在搶答中加入，**則**各端顯示同一活動、正確的自身組別與題目。開始前不得提交答案。
2. **給定**兩組已加入且保持連線，**當**教師開啟或結束搶答，**則**兩組原頁面都能反映同一階段。任一已授權端重新整理時，第一次成功讀取即顯示權威狀態。
3. **給定**學生在教師切換階段時離線，**當**連線恢復，**則**原授權仍有效時自動回到原活動與組別並取得最新階段。原授權失效時，結束前提示重新加入；結束後依第 5 項驗證原瀏覽器的加入紀錄及原組別。
4. **給定**活動已結束，**當**尚未加入者輸入有效代碼，**則**拒絕新加入。
5. **給定**已加入的學生在活動結束後授權失效，**當**回到保有原加入紀錄的同一瀏覽器並成功驗證原組別，**則**可查看該組依 D06 可見的結算結果。若改用其他裝置或瀏覽器，或原加入紀錄已清除，即使輸入正確代碼也不得恢復。

### 使用者故事 3 – 角色與階段限制資料（P1）

教師能管理自己的活動並查看作答狀況。學生在結束前只取得自身可見資料，結束後可查看核准公布的結果。

**優先理由**：權限限制適用於畫面、直接請求及模組之間傳遞的使用者資料。

**獨立驗收**：以兩組測試資料檢查操作權限與各階段的回應內容。

1. **給定**學生、未授權者或無權管理該活動的教師，**當**直接要求開啟或結束活動，**則**拒絕且階段保持原狀。
2. **給定**活動尚未結束且另一組已有作答資料，**當**學生查看畫面或直接讀取活動／作答資料，**則**回應不含另一組的作答內容、已答狀態、順位或勝組。
3. **給定**活動已結束且 003 完成結算，**當**師生查閱結果，**則**教師取得各組答案、順位與勝組，學生取得勝組名稱與答案及自身組別答案與順位。
4. **給定**一筆答案已受理、一筆已抵達但尚未受理，**當**系統確認結束，**則**只有已受理的答案納入結果。

### 邊界情境

- 加入資料無效、組別不屬於該活動或授權已失效時，拒絕操作。結束後既有學生可重新驗證原組別取得結果存取權。
- 重複操作或畫面資訊過期時，活動狀態以系統已確認的階段為準。重新開啟已結束的活動須拒絕。
- 003 尚未完成結算時，已結束仍代表活動階段，結果狀態應如實呈現。學生可見欄位依 D06。

### 功能需求

| FR-002 | 建立活動時固定匯入清單版本及其有序題目識別。既有活動持續使用該版本，改用新版須建立新活動。 | R02、R05、R10、D11 |
| FR-003 | 教師須獨立登入。學生可於結束前使用活動碼及自填組別加入，加入即能看題。系統須將自填組別綁定於該活動，後續以伺服器紀錄為準。此加入方式待雙組確認。 | R01、R05、D03、D04 |
| FR-004 | 只有具該活動管理權限的教師能開啟和結束搶答。階段依序為「準備中 → 搶答中 → 已結束」，已結束不可重開。 | R03、D03 |
| FR-005 | 已授權端須同步權威階段。重新整理或重連時，授權仍有效即自動恢復活動及適用的組別並取得目前階段。學生授權失效時，結束前可重新加入。結束後須在同一瀏覽器保有可由系統驗證的原加入紀錄，並重新驗證原組別，才可恢復結果存取。 | R08、D09 |
| FR-006 | 系統須對每次操作與資料讀取驗證角色及活動範圍，依下表限制回應。 | R01、R04、R06、R09 |
| FR-007 | 002 須提供可供 003 核對的活動、組別、題目及權威階段。只有作答期間且在系統確認結束前已成功受理的答案才計入。 | R03、R05、R07、D02、D03 |

### 角色權限與階段可見資料

| 角色 | 準備中 | 搶答中 | 已結束 |
| --- | --- | --- | --- |
| 授權教師 | 建立活動、查看目前階段及所選題目清單、開啟活動 | 查看目前階段、題目與 003 提供的作答狀況，結束活動 | 查看目前階段、題目與 003 提供的結果 |
| 已授權學生 | 加入後可查看目前階段、自身組別與題目，尚不能作答 | 查看目前階段、自身組別與題目，可按組向 003 提交 | 查看目前階段與自身組別。結算後可看勝組名稱與答案及自身組別答案與順位 |
| 未授權或活動範圍不符 | 可持有效代碼要求加入，授權前不提供活動內容 | 同左 | 停止接受新加入。已加入者可重新驗證原組別，驗證成功後才可讀取結果 |

結束前，學生畫面與服務回應都必須排除其他組別的作答內容、作答狀況、順位及勝組。內部識別、來源格位及憑證只傳遞給需要它們且有權限的模組或角色。

組別由學生加入時自填。系統依加入紀錄限制作答與查閱範圍。自填組別無法驗證學生在教室中的實際分組。

### 主要資料與跨功能介面

欄位是邏輯資料契約，具體傳輸方式與持久化方式留待 plan。

| 方向 | 邏輯資料 | 契約 |
| --- | --- | --- |
| 001 → 002 | 匯入清單識別與版本、可用性、依來源排列的題目識別與顯示題號，包含單題／題組類型與有序作答項目 items | 建立時固定版本與題目識別。題號供顯示，題目識別用來關聯作答。題組語意依 001 格式契約及 D10，以主題號為提交單位，items 為小題。來源格位與憑證由 001 管理。 |
| 002 → 003 | 活動識別、有效角色、活動下的組別識別（學生適用）、權威階段、清單參考與有效題目識別 | 003 依可信的身分與階段確認活動、組別及題目有效。提交受理不得只依賴畫面顯示或用戶自行提供的角色、組別和階段。 |
| 003 → 教師／學生 | 依角色與階段授權的作答狀況或結果，以活動、題目、組別識別建立關聯 | 003 管理提交及結算，並依 D06 與上表公布欄位。 |

- **活動**：活動識別、管理教師、清單參考與當前階段。
- **活動身分**：使用者的有效角色與可操作的活動範圍。
- **活動組別**：活動與組別識別的關聯，供授權及後續提交辨識。
- **匯入清單及題目參考**：清單內有序的題目識別、顯示題號與已確認的題組／小題參考。

## 成功標準

- **SC-001**：以一份三題測試清單建立活動，三題的顯示順序與識別均可對應來源。無效清單案例均未建立活動。
- **SC-002**：一位教師、兩組學生共三端，在開啟與結束兩次操作後都觀察到相同階段。分別重新整理三端，六次首次成功讀取均顯示正確階段。同步延遲須量測，兩秒為組內候選目標。
- **SC-003**：學生與活動無關的教師直接嘗試開啟／結束時，所有請求均遭拒且不改變階段。
- **SC-004**：對兩組分別驗證開始前與作答中的畫面及回應，共四組角色階段組合均無其他組的作答資訊。結算後教師及兩組學生的回應均符合 D06 欄位限制。
