# Feature Specification: 建立活動後顯示學生預覽

**Feature Branch**: `codex/005-preview-before-start`

**Created**: 2026-11-25

**Status**: 實作及自動驗證完成；人工驗收未完成

**Input**: 「我想要按下去建立活動就是學生就能看到題目，搶答沒問題。」本次補齊已同意但尚未完整落實的看題時機與單活動限制；不是新增待表決規則。題目指題號、小題標號與作答欄，不擴充完整題目敘述。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 建立後即可看見活動 (Priority: P1)

老師在開放中的課堂選擇講義並建立活動後，已加入課堂的學生可以看到該活動的題號與作答欄，不必等老師開啟搶答，也不用再次輸入課堂碼。

**Why this priority**: 讓老師能先確認學生看到正確講義，再統一開始搶答，避免把尚未開放誤認為匯入或顯示失敗。

**Independent Test**: 使用老師與兩組學生的獨立瀏覽器；在尚無未結束活動的課堂建立單題及題組活動，核對兩組學生的顯示與等待提示。

**Acceptance Scenarios**:

1. **Given** 課堂開放、沒有未結束活動且兩組學生已加入，**When** 老師成功建立活動，**Then** 兩組自動看到所選講義版本的全部主題號及對應作答欄，並看到「尚未開放搶答」提示。
2. **Given** 活動已顯示且尚未開放，**When** 學生重新整理或重新連線，**Then** 仍在原課堂及原組別，恢復同一活動預覽。
3. **Given** 題組有兩小題，**When** 預覽顯示，**Then** 保留一個主題號、兩個小題標號與兩個作答欄，不把小題變成獨立提交單位。

### User Story 2 - 老師開放後才接受提交 (Priority: P1)

學生可以先看見活動，但只有老師按下「開啟搶答」後才可以作答及提交；開始前的預覽不產生順位或答案紀錄。

**Why this priority**: 顯示時間與搶答起點分開，保留所有組別共同開始的既有規則。

**Independent Test**: 對同一活動分別在開始前、開始後、結束後嘗試提交，核對受理結果及活動識別。

**Acceptance Scenarios**:

1. **Given** 尚未開放，**When** 學生看見預覽，**Then** 作答及提交控制停用；繞過畫面的提前提交也被拒絕，且不建立作答或順位。
2. **Given** 學生正在預覽，**When** 老師開啟同一活動，**Then** 畫面自動轉為可作答，不需重新加入或手動重新整理，題號與講義版本保持一致。
3. **Given** 活動或課堂已結束，**When** 學生嘗試提交或收到較舊狀態，**Then** 不可重新開放提交，延遲答案不可歸入另一活動。

### User Story 3 - 下一活動不打斷既有搶答 (Priority: P2)

同堂一次只能有一個未結束活動，包含準備與搶答階段。老師必須先結束目前活動，才可建立下一活動；歷史活動及結果繼續保留。

**Why this priority**: 課堂切換是既有功能，提前顯示不能破壞目前搶答。

**Independent Test**: 分別在準備、搶答及結束階段嘗試建立下一活動，核對前兩者被拒絕、結束後可建立，且舊答案不會送入新活動。

**Acceptance Scenarios**:

1. **Given** 活動 A 正在搶答，**When** 老師嘗試建立活動 B，**Then** 拒絕建立並提示先結束 A；保留學生畫面及 A 的正常提交，不產生 B。
2. **Given** 活動 A 尚在準備，**When** 老師嘗試建立活動 B，**Then** 同樣拒絕建立，不取代目前預覽。
3. **Given** 活動 A 已結束且課堂仍開放，**When** 老師建立活動 B，**Then** 學生自動看到 B 的準備預覽，A 的歷史與結果保留，A 的延遲提交不得寫入 B。
4. **Given** 活動 A 尚在準備，**When** 老師直接結束 A，**Then** A 轉為已結束、不產生答案或順位，老師可建立下一活動；學生自動看到下一活動預覽。

### Edge Cases

- 建立失敗或選取的講義版本無效：保留原顯示，不發布不存在或不完整的預覽。
- 連續點擊建立或兩個教師視窗同時建立：同堂最多成功建立一個未結束活動，其餘請求被拒絕，不產生隱藏的待開活動。
- 開發階段先前產生的測試資料可丟棄；本次以空白開發 DB 驗收，不做多準備活動的升級、遷移或相容流程。這不代表正常結束活動就刪歷史，也不允許自動清空來源 Google Sheets。
- 狀態更新失敗、重連、回應亂序：顯示連線狀態，恢復最新活動及階段，不以較舊狀態重新啟用提交。
- 學生尚未加入、加入其他課堂或課堂已關閉：沿用既有身分與可見範圍限制。
- 正式搶答模組尚未接入：可驗收預覽與開放狀態切換，但不得以畫面可提交宣稱順位與結算已完成。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 在開放課堂且沒有未結束活動時，成功建立活動必須自動向同堂學生顯示該活動預覽，無須再次加入。
- **FR-002**: 預覽必須包含活動名稱、全部主題號、有序小題標號及各作答欄，與建立時固定的講義版本一致。
- **FR-003**: 未開放搶答時必須明示等待老師開始，停用作答與提交；開始前的提交必須被權限及階段檢查拒絕，不產生答案或順位。
- **FR-004**: 只有授權教師的明確開始操作可開放搶答；建立活動本身不開始計時、不接受提交、不計算順位。
- **FR-005**: 開始、結束及重連後學生必須自動取得正確活動與階段；同一活動從預覽轉為搶答不得要求重新加入。
- **FR-006**: 活動或課堂關閉後必須拒絕提交，舊活動請求不可寫入新活動；已關閉活動不可因狀態重送而重開。
- **FR-007**: 學生可見資料不得包含其他組答案、提交狀況、機敏設定或來源儲存格資訊；既有結束後結果規則維持不變。
- **FR-008**: 同堂一次只允許一個未結束活動，包含準備與搶答階段；已有未結束活動時，介面必須禁止建立下一活動並提示先結束目前活動，繞過介面的建立請求也必須被拒絕。結束後才可建立下一活動，不預建、不自動排隊；歷史活動與結果保留。同時建立請求不得繞過此限制。
- **FR-009**: 建立失敗必須保留原活動顯示；較舊的狀態不得覆蓋較新的活動與階段。

### Key Entities

- **課堂**：學生加入與分組的範圍，具有開放或關閉狀態，以及目前向學生顯示的活動。
- **活動**：固定講義版本、名稱及準備／搶答／結束階段；可顯示不代表可提交。
- **學生預覽**：指定活動中本組可見的題號、小題及作答欄，以及是否允許作答的狀態。
- **活動作答**：屬於特定活動、組別與主題號，僅於開放搶答期間依既有完整題組規則受理。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在本機穩定連線、教師及兩組學生的驗收中，成功建立可顯示活動後，兩組均於 5 秒內看到正確題號與作答欄，無須重新整理。
- **SC-002**: 單題及題組驗收中，顯示的主題數、小題數與作答欄數全部符合所選版本，沒有缺漏或多出欄位。
- **SC-003**: 開始前、活動結束後及課堂結束後的提交案例全部被拒絕，沒有新增有效答案或順位。
- **SC-004**: 老師開始後，兩組均於 5 秒內轉為可作答；活動名稱、識別與講義版本沒有錯置，不需重新加入。
- **SC-005**: 活動切換、重新整理及一次斷線恢復案例中，不出現跨活動誤提交或其他組答案洩漏。
- **SC-006**: 準備、搶答及同時建立情境中，同堂未結束活動數均不超過一個；結束後可成功建立下一活動，歷史資料無遺失。

## Assumptions

- 2026-11-25 使用者回報規則及圖意確認完成，並澄清「大家都已經同意」，本次是補強既有實作，不要求重新表決。確認者姓名與獨立紀錄連結待補，不由 AI 代填。
- 作答欄在預覽時停用，開始後才可輸入；完整題目敘述、預先填答、正式順位／結算及 Google 登入皆不納入本迭代。
- Q1 已確認：同堂僅一個未結束活動，不論準備或搶答，已結束歷史活動數不受限。舊開發資料可丟棄，無保留多準備活動的例外；SC-006 依空白開發 DB 建立的資料驗收。
- 依賴既有課堂加入、固定講義版本與活動階段規則；不改題組整組提交及結果回填規則。
