# 實作計畫：004 課堂加入與同堂活動切換

**分支** `codex/004-classroom-activity-switching`

**日期** 2026-11-25

**依據** [規格](spec.md) · [共同需求 D12–D16](../../docs/shared-requirements.md) · [Issue #5](https://github.com/Afra0704/se2026-group20-speckit/issues/5)

## 摘要

在 002 共用 Flask 應用新增教師課程與一次性課堂。課堂持有學生加入範圍與當前活動指標。活動依舊是 003 受理、結算及 001 回填的唯一識別。不同班次共用講義版本，但各自保存組別與結果。

## 技術環境

- 延用 Python 3.13、Flask、Jinja、原生 JavaScript、SQLite、uv 與 pytest。
- 以 `GUIDED_NOTES_CLASSROOM_MODE=1` 啟用 004 課堂路由及資料表，使用獨立的開發資料庫，預設為 `instance/classroom-004.sqlite3`。初始化可重跑。004 若指向含舊 002 結構的資料庫，啟動時明確報錯且不改動該檔。原啟動方式繼續服務 002 單活動流程。
- 階段同步沿用約一秒的單一輪詢。載入及重連立即查課堂狀態。檢查 `classroom_id` 與遞增的 `state_version` 才採用回應。

## 圖表與實作結構

- [組件圖](../../diagrams/004-component.puml) 對應 `src/guided_notes/activities/` 的課程、課堂、活動層級，教師入口接 `notes/` 的課程講義，學生作答與結果仍由 `quiz/` 管理。
- [類別圖](../../diagrams/004-class.puml) 對應課程、課堂、課堂組別／加入證明、活動、001 清單版本及結算快照。詳見 [資料模型](data-model.md)。
- [時序圖](../../diagrams/004-sequence.puml) 對應先選課程、加入一次、開始和關閉、同步切換、原瀏覽器查結果及正式回填。

開始活動、結束活動、關閉課堂、學生加入和 003 收件均使用既有 `write_transaction()`。開啟活動在同一交易核對課堂尚開放、教師為擁有者及沒有搶答中活動。關課一併結束仍在搶答中的活動，提交後才公布階段；每次收件仍使用原請求中的活動識別並查驗課堂、當前活動和組別。

狀態查詢在同一 SQL 查詢或同一讀取交易取得課堂版本和目前活動階段，避免回應混合兩個時間點的欄位。教師擁有者經由活動、課堂、課程關聯解析。學生同步時只收當前活動資料，歷史結果另外逐場驗證。

教師在課程內匯入講義時，001 建立預覽並綁定課程，確認時再檢查教師與課程。002 建立活動時使用 001 的課程範圍查詢，驗證課程、匯入識別與選定版本才固定題目。函式簽名依 001 分支 `418365f` 的交接對齊，真實驗收等合流。學生直接查指定活動結果時，跨堂拒絕；同堂結算中只回狀態。

先用替代課程講義、受理及結果提供者獨立驗證 004，再串接實際 001 和 003。完整排名與回填實作仍由原模組負責。
