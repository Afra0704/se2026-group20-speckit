# Phase 0 研究

| 決策 | 理由 | 評估過的方案 |
| --- | --- | --- |
| 004 延用 002 共用 Flask app 與 SQLite | 現有登入、CSRF、資料庫與受理邊界可重用，同一交易可保護切換與關閉。 | 分拆課堂服務會多出跨系統交易協調；目前本機展示無此需求。 |
| 課堂以當前活動指標及狀態版本同步 | 既有一秒輪詢可延用。版本搭配課堂識別可拒絕晚到的舊回應。指標可保留最近已結束活動，供學生知道目前在等切換。 | 以最新時間排序推測當前活動容易在同名、操作者競爭或已結束的場次上產生歧義。 |
| 課堂分組與 003 活動結果分離 | 學生只加入一次。作答記錄仍用活動及組別識別，保留每次活動的截止和回填穩定性。 | 每次切換複製組別會引入重新授權和錯位風險。 |
| 使用不同名稱的空白開發資料庫 | 符合雙組確認的測試範圍，舊資料庫可留作備查。 | 在原檔上清表或遷移舊活動超出此次開發驗收需求。 |
