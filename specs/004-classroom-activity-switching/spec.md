## 使用者情境與驗收

### US1 教師重用課程講義並管理課堂（P1）

教師建立、命名和查看自己擁有的長期課程，可選擇 001 已匯入的講義版本，每次上課建立新的課堂。以同一課程、兩份測試講義與兩個班次即可獨立驗收。

1. 同一課程保存兩份講義，教師建立上午與下午課堂，兩堂有不同加入碼。任一課堂都可選用相同講義版本。
2. 無權教師直接操作其他教師的課程、課堂、講義或活動時，後端拒絕。
3. 教師可在歷史紀錄辨識各課堂及其活動，活動可依名稱、時間與狀態辨識。同名活動有各自獨立識別。

### US2 學生加入一次，跟隨教師切換活動（P1）

學生在課堂以加入碼與自填組名加入，等候活動並參與，同堂切換無須重新加入。以同堂兩組、兩份講義與另一堂同名組別驗收。

1. 同一課堂相同組名依既有整理規則歸為一組，另一課堂的同名組別獨立。等待期間沒有可提交的活動。
2. 教師啟動第一個活動後，學生畫面同步其階段。結束後仍留在課堂；下個活動開始時自動切換並沿用原分組。畫面可區分等候、搶答中、活動已結束及課堂已結束。
3. 同堂兩個啟動請求競爭時，最多一個活動進入搶答中。舊活動延遲提交不得寫入新活動。
4. 重新整理及重連會恢復目前課堂、分組和權威活動。授權失效的結果恢復沿用 D09 的原瀏覽器證明，新加入仍受課堂是否結束的限制。

### US3 關課及保留歷史與回填（P1）

教師確認關課後停止加入和提交，仍可檢查各次活動和結算。以空白開發資料庫建立有進行中活動的課堂來驗收。

1. 教師取消確認不改變狀態。確認後課堂結束，進行中的活動也結束，後端拒絕後續加入、提交和重開。
2. 同一份講義建立的兩個活動各自保留結果。結算後供 001 使用的快照精確對應指定活動、結果版本與匯入版本。未結束回 `ACTIVITY_NOT_ENDED`，已結束未結算回 `RESULT_NOT_READY`。
3. 從空白開發資料庫初始化，建立課程、課堂與活動。結束課堂後，新版建立的活動和結果仍可查閱，來源 Google Sheets 資料保持原狀。
4. 關課後，既有學生在原瀏覽器驗證成功，可選看同堂各已結算活動的勝組與本組結果。其他課堂的活動、未結算資料或非 D06 欄位均不提供。

## 需求

| 編號 | 規則 |
| --- | --- |
| FR-001 | 教師可建立、命名、查看自己的課程。先選課程，再依 001 契約匯入或選擇該課程有權存取的講義與版本。教師權限由後端檢查。 |
| FR-002 | 課堂屬於一門課程，有獨立加入碼及進行／已結束狀態。組別和加入證明綁定課堂。 |
| FR-003 | 一次加入後，學生可在同堂不同活動沿用組別。保持連線、重新整理及重連時取得權威課堂及當前活動，較舊回應不得倒退畫面。 |
| FR-004 | 同一課堂同時最多一個搶答中活動。每次活動使用獨立識別、預設講義名稱且可自訂名稱，固定已確認的講義版本及題目。提交以原活動識別與系統確認順序判定。 |
| FR-005 | 經教師確認關課時，進行中的活動一併結束。關課後拒絕新加入、提交及重開，同時保留講義和歷史。 |
| FR-006 | 各活動獨立結算。關課後既有學生可依原瀏覽器證明選看同堂各已結算活動，依 D06 限制可見欄位。001 只取得指定活動的完整已結算快照。 |
| FR-007 | 驗收使用新的空白開發資料庫，操作指南記錄初始化方式。既有 002 測試資料、活動碼及授權憑證不納入遷移。 |

## 主要實體

- **課程**：教師擁有的長期教材單位，關聯講義及各次課堂。
- **課堂**：一次性場次，內含加入碼、組別、加入證明和當前活動。
- **活動**：課堂內的一次搶答，固定講義版本並獨立保留答案及結果。
- **講義版本**：001 管理的不可變匯入版本，保留來源工作表對應。

## 成功標準

- SC-001：教師在同一課程建立兩堂課，兩課堂均可用同一份講義，加入碼與同名組別皆獨立。
- SC-002：教師和兩組學生走完兩個活動。兩組各加入一次，切換與重整時仍可辨識原組別和當前活動。
- SC-003：並行啟動最多一個成功；切換後的舊提交及關課後的加入／提交全數遭拒。
- SC-004：從空白開發資料庫建立同講義兩個活動，關課後仍可分別查閱結算及回填資料，來源 Sheets 未被清空。

## 待釐清及相依

1. 001／002 需共同確認課程選擇、講義列表與版本、本課堂狀態以及錯誤回應的契約。候選方案見 [接線草案](integration-draft.md)。

正式 Google Sheets 匯入與回填由 001 負責，完整排名、作答與結算由 003 負責。
