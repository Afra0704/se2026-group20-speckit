# 送答回饋介面契約

## 既有 HTTP

`POST /activities/{activity_id}/submissions` 沿用 CSRF、課堂分頁憑證、`Idempotency-Key`、`question_id` 與 `items`。正式路徑成功為 201 且 `status=accepted`。重試沿用同一 UUID 及內容。舊客戶端仍可只讀 `error`。

已授權本題的 `INVALID_ITEMS` 可選擇性回傳 `invalid_item_ids`，僅含預期題組中可定位的空白或漏填 ID。無法安全定位時使用本題通用提示。非本題的、重複的或格式錯誤的項目一律拒絕，且不可藉錯誤列出其他題目或組別資訊。

驗空以前端實作與既有 Python 3.13 無參數 `str.strip()` 一致為準。空字串或整串皆為下列碼位時視為空白：U+0009–U+000D、U+001C–U+001F、U+0020、U+0085、U+00A0、U+1680、U+2000–U+200A、U+2028–U+2029、U+202F、U+205F、U+3000。U+FEFF 不在既有集合。判斷只用於驗空，提交與儲存保留原字串。

## UI 與狀態

| 狀態或回應 | 本題畫面及操作 |
|---|---|
| 未提交 | 「提交」。欄位驗空不建立送答操作。錯誤標在欄位旁並移焦第一個錯誤。 |
| 送出中 | 顯示「送出中」，暫禁提交與重試。編輯中的資料與已發送內容分離。 |
| 201 受理 | 顯示「答案已受理」。可改答時按鈕為「重新提交」。重送回原受理不增加順位紀錄。 |
| 明確拒絕 | 顯示本題原因，保留輸入。400 欄位錯誤可修正，409 階段限制提示目前不可送。首次操作的 429 顯示稍後再試，可依 Retry-After 控制再次送出。重送衝突依下方例外處理。 |
| 結果未知 | 顯示「送答結果未確認，伺服器可能已受理」，保留原 UUID 和內容。只可手動重試此次送答，編輯欄位仍可用；原操作結果確定後才可送修改內容。 |

先前已未知時，重試遇到限流、資格拒絕、CSRF 或其他發生於查重前的阻礙，不視作原操作已拒絕。取得資格與終態由 #17 處理。正式路徑先以已授權的活動、題目、組別及 UUID 查重，再檢查是否能新受理。因此 201 accepted 或查重後的 INVALID_PHASE 可以結清原操作。無法確認原操作時保留未決資料，按既有頁面終態及清理契約限制操作。重送衝突不得換鍵自動重送。

每次更新前核對課堂、活動、組別、題目、文件作用域、畫面世代與目前嘗試。晚回不清除新操作。逐欄錯誤用 aria-invalid 並關聯文字，本題回饋有可由輔助技術讀出的狀態區。頁面連線訊息單獨呈現。

重試收到 `409 SUBMISSION_REPLAY_CONFLICT` 表示本次使用的 UUID 與既有內容不符，原答案的受理狀態無法由本次回應確認。原未決操作和目前編輯文字都保留，該操作停用同題的新提交及同內容重試。提示「無法核對原送答，請向老師確認，或使用『重新加入課堂』。」取消重新加入保留現況，確認後按 #17 只清本頁。此例外保留其未決性，重整同頁後仍顯示衝突提示。舊版未決資料缺少衝突標記時仍按一般結果未知處理。
