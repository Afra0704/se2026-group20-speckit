# 003 資料模型

| 實體 | 欄位與約束 |
| --- | --- |
| 既有活動與固定題目 | `activity_id`、課堂及教師歸屬、`phase`、`import_id`、`import_version`。依 `(activity_id, question_id)` 取建立活動時保存的題目與小題來源識別。由 002／004 管理。 |
| 受理操作 | 單調且唯一的伺服器 `accept_seq`、活動與題目、組別、本次操作識別、原字串答案及可重建的安全受理收據。活動、題目、組別、操作識別唯一。提交整題或整個題組。 |
| 目前有效提交 | 每個 `(activity_id, question_id, group_id)` 至多一個有效受理識別。指標只能指向相同範圍的受理操作。新操作成功時在同一交易更新指標。 |
| 結算待辦與發布 | 每活動一筆，CLOSED 同交易新增待辦。發布保存結果版本、嚴格快照及結果資料。待辦轉成已發布後不可改回，重複讀取重用同版。 |

## 不變條件

- 活動與題目使用既有識別與關聯。正式課堂的組別由課堂資格取得，非課堂相容入口從原 `activity_groups` 取得。兩種群組資料來源不可互換。
- 答案鍵與固定題目的小題集合完全一致。每個值為去空白檢查後非空的字串，保存與交付仍用原字串。
- 排行只取有效指標，按 `accept_seq` 遞增並對該題重新編列連續名次。既有收據的重試不修改有效指標。即使重試被取代的舊提交也一樣。
- 結算針對固定題庫產生每題一個 unit。勝組帶全組完整答案。無勝組時標示 `no_winner` 並交付空答案集合。
- 待結算狀態與歷史無正式資料是不同情況。沒有 003 待辦的歷史 CLOSED 活動不補造結果。有待辦但無任何有效提交的活動可正常結算為全部無勝組。
- 003 schema 可重跑，與既有資料共用同一 SQLite。啟動及 `init-db` 安裝新表，保留 Google instance、授權密文、課程、課堂與講義歷史。
