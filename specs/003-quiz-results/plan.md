## 摘要與技術背景

在既有 Python 3.13／Flask app 與 SQLite 內接上正式受理、教師進度、師生結果及 001 快照。重用 Google 教師登入、課堂資格、CSRF、原生 JavaScript 與一秒輪詢。共用寫入交易決定受理與截止，結算在關閉後以另一短交易發布。pytest、Node 與暫存 DB 覆蓋自動驗證，兩份講義副本與教師加兩組學生覆蓋端到端操作。正常本機操作採兩秒內反映進度或已可取得結果為觀察目標，記錄實際環境與量測值。

## 專案結構

- `src/guided_notes/quiz/` 沿用三個路由／gateway，加入受理、結算與資料儲存。
- `src/guided_notes/activities/` 分開原收據範圍與新送答資格，沿用 `teacher.transition` 的關閉路徑，課堂歷史入口支援已結束活動。
- `src/guided_notes/db.py` 與 `__init__.py` 安裝可重跑的 schema、註冊正式 provider、保留明確配置的測試覆寫。
- `src/guided_notes/static/classroom.js`、`activity-sync.js` 處理同次重試、主動再送、逐小題結果與活動切換。
- `tests/` 沿用單元、契約、整合與 Node 測試入口。

## Phase 1：設計

1. **受理**。每次主動送答有獨立操作識別；網路重試沿用同一識別與完整內容。瀏覽器在送出前以 `sessionStorage` 暫存未確認的操作，同一分頁重新整理後，只在恢復原活動、原組別及合法資格時提供手動重試。先核對可信原組別及固定題目。命中原操作時回既有受理結果。新送答才在共用寫入交易重驗目前課堂、目前活動、LIVE 與可提交資格，分配唯一順序、保存答案並取代有效指標。commit 成功後才能回覆 accepted。
2. **截止與恢復**。教師結束、關課隱含結束、既有相容入口都透過共用轉換。CLOSED 與待結算標記同交易。關閉 commit 後嘗試完成結算。失敗保留待辦，正常啟動有限批次及已授權結果、課堂歷史與 001 查閱可重試。一次結算交易驗證固定題庫、保存全份結果及版本；已公布直接讀原資料。舊資料庫的歷史 CLOSED 活動若無正式標記，保留為無可用正式結果。
3. **結果與回填**。教師 LIVE 看組別提交狀況，學生只得可見狀態。依 D22，課堂開放時有有效同堂組別資格的學生可查已結算活動，包含新加入者；關課後沿用 D16 的原瀏覽器證明。已結算依 D06 投影逐小題答案。001 從原 `get_ended_snapshot` 取得含 `contract_version: 1` 的快照。發布前從 001 存檔讀取活動固定的教師、`import_id` 及 `import_version` 對應的完整歷史清單，執行嚴格驗證。排名及作答仍以活動固定題目與有效提交為準。
